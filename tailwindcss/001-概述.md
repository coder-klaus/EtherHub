Tailwind CSS 在构建时 通过正则 扫描所有需要扫描的文件「 通过配置文件说明 」，并根据功能类生成对应静态css文件

+ 官方的 [**Tailwind CSS Prettier 插件**](https://github.com/tailwindlabs/prettier-plugin-tailwindcss)，该插件会根据推荐的类名顺序自动对你的类名进行排序



Tailwind CSS 默认自带了

1. Tailwind 会自动添加必要的`浏览器前缀`并`原生支持嵌套`和`css变量`
   + 在底层，Tailwind 使用 [**Lightning CSS**](https://lightningcss.dev/) 来处理像 CSS
   + **Lightning CSS** => Rust版本的postcss
   + 无需在使用插件`autoprefixer`
2. Tailwind CSS 提供了对 `@import` 的内置支持，可以自动解析通过`@import`导入的样式文件 
   + 无需额外配置 `postcss-import` 插件来解决这个问题 



样式分为固定值样式 「 `display`、`position`等 」 和 动态值样式 「 `color`、`font-size`等 」

对于动态值样式，tailwind css内部使用css变量来实现，这些css变量又被叫做主题变量，或 设计令牌





Tailwind CSS可以和css modules一起使用，但不推荐

+ css modules最主要功能是解决样式冲突，而tailwindcss已经解决了这个问题
+ 每个css modules都会被构建工具进行处理，写在css modules中的样式就会需要经过多次tailwindcss的处理
+ 像vue，svelte这种使用SFC来管理组件的，其style处理方式类似于css modules, 所以尽可能使用功能类，而不是使用style块



如果你在一个项目中使用了 50 个 SFC（单文件组件），并且每个组件的 `<style>` 块都单独包含了 Tailwind CSS 的类名，那么在构建过程中，Tailwind CSS 可能需要对这些样式进行多次处理。「 CSS Modules 和 SFC style块的处理方式都是如此 」

但如果你直接将 Tailwind CSS 的类名写在 组件的 `<template>` 中，而不是通过 `<style>` 块来定义样式，那么 **Tailwind CSS 不会逐个组件重新编译整个模块**，而是会扫描整个项目的模板文件来提取所有使用的类名，并生成对应的 CSS 样式。



此外因为css modules 是单独的样式模块，所以无法直接使用功能类

解决方法是 「 任选其一 」

1. 使用主题变量作为样式值

2. 将功能类定义到全局样式文件，然后通过`@reference`指令引入

   + `@reference`是仅在css modules和tailwindcss中存在的工具

     - **`@reference`**
       - 仅作为引用，告诉工具全局样式的存在。
       - 不会将全局样式直接嵌入组件的 CSS。
       - 通常用于优化性能。

     - **`@import`**
       - 将全局样式的内容直接嵌入到组件的 CSS 中。
       - 可能导致样式体积膨胀，影响构建性能。
