Vue Options API (VOA) 通过 data/methods/mounted 等不同配置项完成对应功能

然而，这种方式在组件变得更大、更复杂时，可能会导致以下问题：

1. **逻辑分散**：同一个功能的代码逻辑被拆分到多个属性中，导致碎片化，增加了代码的复杂性。
2. **频繁跳转**：在处理单个逻辑关注点时，需要在代码中频繁跳转到不同的属性，降低了开发效率。
3. **复用性差**:  配置对象通过`mixin`实现配置复用，容易出现命名冲突且不易复用

而这种逻辑分散的代码使得理解和维护复杂组件变得更加困难

为了解决这些问题，Vue 3 引入了 **Composition API (简称 VCA)**

1. **函数式编程:** 用函数形式将相关逻辑组织在一起
   + 内聚性更高
   + TypeScript兼容性更高
   + tree-shaking性能更高，构建后体积更小
   + 复用性更高

## setup

1. 一个用于编写VCA逻辑的option选项
2. 不能再setup中使用`this`
4. setup option可以替代绝大部分`vue2 option`，但不能替换全部
   + 如 props，emits，name，components选项还是使用以前方式进行接收

```js
{
  // 参数一 => props
  // 参数二 => ctx 「 除props外的组件所有都被封装到了ctx中，如attrs，slots，emit等 」
	setup(props, ctx) {
    // 在setup中定义的默认只是普通数据，需要通过VCA API手动转换为响应式数据
    
    // setup方法可以返回一个对象，该对象中的的属性和方法可以在模板中直接使用
    // setup方法也可以返回一个函数，该函数直接充当render方法
    return { }
  }
}
```

```vue
<template>
  <div>
    <div>{{ count }}</div>
    <button @click="increment">+1</button>
  </div>
</template>

<script>
import { ref } from 'vue'

export default {
  setup() {
    return {
      count: ref(0),
      increment: () =>  count.value++
    }
  }
}
</script>
```



### [script setup](https://juejin.cn/post/7002490039066165279)

1. `setup`函数的语法糖
2. 在编译时会自动转换为`setup`函数

```vue
<script setup>
  // script setup => 顶层变量 可以直接在模板中使用
  // 所以导入的组件无需注册即可使用
  import Cpn from './components/Cpn'
</script>
```

```vue
<template>
	<div>
    <!-- defineProps声明的props可以直接使用，无需props.name -->
		{{ name }}
	</div>
</template>

<script setup>
// defineProps 和 defineEmits 以及 defineExpose 都是script setup∂提供的编译时宏，可以不引入直接使用
  
// defineXxx格式是编译时宏，会在编译时应用特殊操作，无需显示引入
// => defineProps => 接收props
// => defineEmits => 声明事件
// => defineExpose => 定义向外暴露的信息
// => defineOptions => 定义options选项
// 编译时宏 在编译后会被抽取为对应的option，所以只能顶层导入的内容，不能使用script setup中定义的局部变量

// props是只读的
const props = defineProps({
	name: {
		type: String,
		default: 'Klaus'
	}
})

const emits = defineEmits(['cpnClick'])

const cpnMsg = 'hello cpn'

// 在vue3中，父组件通过dom ref获取子组件时，得到的是空对象
// 我们可以手动需要暴露需要给外界访问的状态和方法
// => option api 使用 expose选项
// => script setup 使用 defineExpose编译宏
defineExpose({
	cpnMsg
})
</script>
```



#### 在TypeScript中使用

```ts
// 定义父组件传入的props类型
interface Props {
  msg: string
  bar?: number
}

// 通过编译时宏 withDefaults 来设置props的默认值
const props = withDefaults(defineProps<Props>(), {
  msg: 'hello',
})

const emit = defineEmits<{
  // e => 事件名，后续为传入的参数
  (e: 'change', id: number): void
  (e: 'update', value: string): void
}>()
```

#### 顶层await

顶层的 await 可以直接在 `<script setup>` 里面使用。

由此产生的 `setup ()` 函数将自动添加 `async`

```vue
<script setup>
  const post = await fetch('/api/post/1810166').then(res => res.json())
</script>
```



#### 与普通 script 一起使用

1. 普通`script` 可以和 `script setup`一起使用
2. `script setup` 会被编译为`返回render方法`的`setup函数`

所以，普通script只会在首次引入，被转换为标准化配置对象时被执行一次

而`script setup` 则会在组件每次调用，创建对应实例时被回调多次

```vue
<script>
  export default {
    name: 'CustomName',
    inheritAttrs: false
  }
</script>

<script setup>
  //script setup logic
</script>
```



## hook

1. hook是使用了VCA的自定义函数
2. 用于组件逻辑的抽取和代码的复用
3. 一般推荐使用`useXxxx`格式进行命名

```js
import { ref, watch } from 'vue'

export default function useTitle(title = '') {
	const titleRef = ref(title)

	watch(titleRef, newV => {
		document.title = newV
	}, {
		immediate: true
	})

	return {
    titleRef
  }
}
```
