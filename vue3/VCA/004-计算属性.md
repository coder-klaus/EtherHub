## computed

返回值是一种特殊的ref => `computedRefImpl`

```js
import { ref, computed } from 'vue'

const firstname = ref('Klaus')
const lastname = ref('Wang')

const username = computed(() => firstname.value + ' ' + lastname.value)

const fullname = computed({
  get: () => firstname.value + ' ' + lastname.value,

  set(v) {
    const names = v.split(' ')
    firstname.value = names[0]
    lastname.value = names[1]
  }
})
```



## DOM Ref

```vue
<template>
  <div>
    <div ref="divRef">foo</div>
    <Cpn ref="cpnRef" />
  </div>
</template>

<script>
import { ref, onMounted } from 'vue'
import Cpn from './components/Cpn'

export default {
	components: {
		Cpn
	},
  setup() {
    let divRef = ref() // divRef 默认值是 { value: undefined }
    let cpnRef = ref(null) // cpnRef 默认值是 { value: null }

    // 组件挂载完成前和组件卸载后，dom ref值都无法正常获取
    onMounted(() => {
      console.log(divRef)
      console.log(cpnRef)
    })

    return {
			divRef,
			cpnRef
    }
  }
}
</script>
```



```vue
<template>
  <div class="container">
    <!-- 基础组件 -->
    <Child :ref="el => getSectionRef(el, 'Child')" />

    <!-- 按钮组件 -->
    <Button :ref="el => getSectionRef(el, 'button')" />
  </div>
</template>

<script setup>
import Child from './components/Cpn.vue'
import Button from './components/Button.vue'

// 使用Map存储所有组件引用
const componentRefs = new Map();

// 如果dom ref绑定为函数，就可以实现dom ref的批量获取
// 函数会在挂载完，卸载后，和更新时 被自动回调
const getSectionRef = (el, name) => {
  if (!el) {
    componentRefs.delete(name);
    return;
  }

  // 将组件引用存储在Map中
  componentRefs.set(name, el);
};
</script>
```

## provide/inject

```js
import { provide, ref } from 'vue'

// provide(key, value)
// 注入的数据推荐写成只读computedRef，并注入修改该计算属性的方法「 保证单向数据流 」
provide('name', ref('Klaus'))
```

```js
// inject(key, defaultValue) => defaultValue是可选的，不传即为undefined
const name = inject('name')
const age = inject('age', 23)
```

> 只有定义在`setup`方法中的`ref`在模板中使用时才会自动解包
>
> 所以如果通过option api接收祖先组件注入的ref时，对应ref在模板中不会自动进行解包



## watch

`const 清理函数 = watch(监听源, 监听回调，配置对象)`

+ 清理函数仅仅只是停止监听，不是阻止响应式

```js
const unWatch = watch(
  userInfo, 
  (newV, oldV) => console.log(newV, oldV), 
  {
  	immediate: true
	}
)
```



和vue2不同, 监听对象为reactive对象，自动开启深度监听

```js
import { reactive, watch } from 'vue'

const user = reactive({
  name: 'Klaus',
  age: 18,
  friends: ['John', 'Jane', 'Jack']
})

function handleClick() {
  user.friends.push('Jill') // 会触发watch
}

watch(user, (newValue) => console.log(JSON.stringify(newValue)))
```



而`ref`对象等其它响应式对象则默认不会开启深度监听，需要手动监听

```js
import { reactive, watch } from 'vue'

const user = ref({
  name: 'Klaus',
  age: 18,
  friends: ['John', 'Jane', 'Jack']
})

function handleClick() {
  user.friends.push('Jill') // 会触发watch
}

watch(
  user, 
  (newValue) => console.log(JSON.stringify(newValue)),
  { deep: true }
)
```



`watch` 中 获取的到新值和旧值 都是深度解包后的原始值

```js
const x = ref(0)
const y = ref(0)
const user = reactive({ name: 'Klaus' })

// 单个 ref 
watch(x, newX => {
  console.log(`x is ${newX}`)
})

// 单个 reactive
watch(user, newX => {
  console.log(newX)
})

// getter 函数 => 本质就是计算属性
watch(
  () => x.value + y.value,
  (sum) => {
    console.log(`sum of x + y is: ${sum}`)
  }
)

// 多个来源组成的数组
watch([x, () => y.value], ([newX, newY]) => {
  console.log(`x is ${newX} and y is ${newY}`)
})
```



### watchEffect

侦听器的回调使用与源完全相同的响应式状态是很常见的，此时就可以使用对应语法糖`watchEffect`

```js
const stopWatch = watchEffect(() => {
  console.log(count.value)

  if (count.value >= 10) {
    stopWatch()
  }
})
```

1. `watchEffect`不是惰性的，即`immediate`强制开启 => 首次执行，用于收集依赖

2. `const 清理函数 = watchEffect(回调函数，配置对象)`

   + 配置对象没有`immediate`, 但是存在`flush` 配置项
   + `flush`表示副作用回调执行时机
     1. 默认值 => pre => 状态更新完毕，dom更新之前
     2. post => 状态和dom都更新完毕后执行回调 => 对应语法糖`watchPostEffect`
     3. sync => 状态改变，副作用和dom同步更新，放弃批处理操作 => 对应语法糖`watchSyncEffect` => 不推荐

   

### watch vs watchEffect

1. watch默认是惰性的，第一次不会执行，而watchEffect默认不是惰性的，必须第一次执行以收集对应的依赖

2. watch在数据发生改变的时候可以获取对应的新值和旧值，而watchEffect只能拿到对应的新值

3. watch可以自定义需要监听的数据源，watchEffect是自动收集对应的数据源，只要数据源中的某一项发生了改变，那么watchEffect的整个回调就会被重新执行
