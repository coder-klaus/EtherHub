Vue 的官方发音是「view」，而不是「v-u-e」

Vue 是一种流行的用于构建用户界面的渐进式框架

渐进式框架的一个核心理念是允许开发者根据项目需求逐步采用框架的功能，而不是强制性地将整个项目完全迁移到该框架上

+ Vue 的功能被分解为多个可选模块，开发者可以根据项目需求逐步引入这些模块

+ vue可以和其余框架在项目中共存，而不是整个项目都使用vue开发



## MVVM

传统开发是 获取DOM，编写逻辑，更新DOM

现代前端开发逻辑是 **放弃直接操作 DOM**。

+ 开发者不再需要手动获取 DOM 元素并修改它们的内容，而是通过数据驱动视图更新。
+ 简单来说就是只要管业务逻辑，至于界面更新，直接交给框架去做就行



Vue 所基于的设计模式是 **MVVM**（Model-View-ViewModel）。

+ React类似于 MVC => 状态改变视图更新
+ Vue采用MVVM => 状态改变视图更新 + 视图状态改变状态更新 「 双向数据绑定 」
  +  视图状态只有表单元素存在自己状态，所以 视图状态改变状态更新 就是 表单元素改变对应状态改变
  + vue在整个MVVM中，充当的就是 ViewModel
  
  

- Vue 的核心思想是操作数据，而非直接操作 DOM。
  - 传统开发流程：
    - 获取 DOM 元素。
    - 修改样式或内容。
  - Vue 的开发流程：
    - 构建数据。
    - 构建视图（通过模板语法）。
    - 修改数据，视图自动更新。



## vue2中的vue

在 Vue 2 中，Vue 是一个构造函数（类）。开发者需要通过 `new Vue()` 创建 Vue 实例来构建项目。

```js
const vm = new Vue({
  // vue2 根组件状态为对象「 居多 」，也可以是返回状态对象的函数。而在组件中必须是返回状态对象的函数
  // 这么做是为了避免多个组件之间状态对象引用一致，相互污染
  // vue3中，无论是根组件还是子组件，状态必须是返回状态对象的函数 「 如果还是使用options api 」
  data: {
    count: 0
  },
  methods: {
    increment() {
      this.count++;
    }
  }
});
```

Vue 2 使用 **Options API** 来配置实例。Options API 是一种基于配置项的模式，开发者通过传入各种配置项（如 `data`、`methods` 等）来实现功能。

这也就意味着，在Vue项目运行时，存在全局对象`vm`，我们可以在控制台中通过直接操作`vm`来进行对应的调试「 例如 `vm.xxx = yyy` 」

其次，类的实例和实例之间是相互独立的，这也就意味着Vue 支持在同一页面中创建多个实例，每个实例都有自己的数据和逻辑。
