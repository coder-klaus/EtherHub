在 Vue 中构建视图时，有两种常用的语法：**模板语法（template）** 和 **JSX**。

其中，模板语法是 Vue（无论是 Vue 2 还是 Vue 3）中使用最广泛的一种方式。



模板语法 由 小胡子语法 和 Vue指令 共同构成

+ 在 Vue 中，所有以 `v-` 开头的内容都被称为**指令**。
  + 指令的作用是为标签设置自定义属性，Vue 会在编译视图时根据这些自定义属性进行处理，从而实现不同的效果，主要用于执行一些特殊的 DOM 操作
  + 指令的值可以是任何合法的 JavaScript 表达式，Vue 会将表达式计算后的结果渲染到视图中

## v-html 和 v-text

`v-html` 和 `v-text` 是 Vue 中用于为非表单元素设置内容的指令。

**`v-html`**

- 将绑定的内容作为 **HTML 字符串** 进行解析，并渲染为真实的 DOM 结构。
- 不会对 HTML 字符串进行转义，因此可能存在 XSS（跨站脚本攻击）风险，开发时需要手动避免。
- 类似于 JavaScript 的 `innerHTML`。

 **`v-text`**

- 将绑定的内容作为普通文本渲染到页面上。
- 功能与插值语法（`{{ }}`）一致，但灵活性不如插值语法。
- 类似于 JavaScript 的 `innerText`。



在项目中，

+ 如果你需要给非表单元素设置内容，通常会用小胡子语法。
+ 当需要将字符串中的 HTML 标签解析为 DOM 结构时，就要用 `v-html`。
+  `v-text` 的用途相对较少，因为它和小胡子语法的功能类似。



## 控制元素显示

- `v-show` 和 `v-if` 的值是布尔类型（true 或 false）。如果值为 true，元素会显示；如果值为 false，元素会隐藏。
- `v-else` 和 `v-else-if` 是配套使用的，用于实现条件判断。

**实现方式**

- `v-show` 是基于 `display` 样式来控制显示和隐藏，元素始终存在于 DOM 中。
- `v-if` 是通过动态创建和销毁 DOM 元素来控制显示和隐藏，元素在 DOM 中可能不存在。

如果同时使用 `v-show` 和 `v-if`，`v-if` 的优先级更高，因为 `v-if` 是控制元素是否渲染，而 `v-show` 是基于已经渲染的元素来控制显示和隐藏。

**适用场景**

+ 如果需要优化初次渲染性能，或者场景中不需要频繁切换，可以使用 `v-if`。
+ 如果需要频繁切换显示和隐藏，使用 `v-show` 更合适。选项卡切换。



 Vue 要求 `v-if`、`v-else-if` 和 `v-else` 必须是相邻的，不能被其他元素隔开

```vue
<h1 v-if="level === 1">标题1</h1>
<h2 v-else-if="level === 2">标题2</h2>
<h3 v-else>标题3</h3>
```

这种写法类似于 JavaScript 中的 `if-else if-else` 语句。



Template 的可读性更强，但编程性相对较弱，而JSX编程性强，但可读性相对较弱

```jsx
const element = React.createElement(
  `h${level}`, // 动态生成标签名
  { className: 'title' }, // 添加属性
  '标题内容' // 添加内容
);
```



## v-for 

`v-for` 用于循环创建元素。 => 那个元素需要被重复多次创建，`v-for`就加在那个元素上

`v-for` 的基本语法是：

```html
<li v-for="(item, index) in list" :key="item.id">
  {{ index }} - {{ item.name }} - {{ item.age }}
</li>
```

- `item` 表示当前迭代的每一项。
- `index` 表示当前项的索引。
- `list` 是要迭代的数据源，需要是一个可迭代数据，通常是一个数组。
- `:key` 是必须的，用于标识每个循环生成的元素的唯一性，用于DOM-DIFF



在使用 `v-for` 时，Vue 要求为循环生成的元素设置唯一的 `key` 值。`key` 的作用是帮助 Vue 的虚拟 DOM 更高效地更新和复用元素，从而优化性能。

`key` 的值应该是循环数据中唯一的标识符，如果数据中没有唯一标识符，可以暂时使用索引 `index` 作为 `key`。不过，使用索引作为 `key` 在某些场景下可能会导致性能问题。



**可以迭代的数据类型**

1. `(数据项，索引) in 数组`
2. `(数据项，索引) in 数字` => 假设数字是5，实际渲染的是 `[1, 2, 3, 4, 5]`
3. `(数据项，索引) in 字符串` => 实际渲染的是 `字符串.split('')`
4. `(value，key, 索引) in 对象`



**注意点**

1. 括号可以省略，不推荐
2. in 和 of 是等价的
3. 可以迭代所有可迭代数据 和 对象 
   + 除了上述规则外，其余可迭代对象一律通过`Array.from`转数组后进行渲染



在 Vue 中，`v-for` 和 `v-if` 的优先级不同：

1. 在 Vue 2 中，`v-for` 的优先级高于 `v-if`。
   + 在 Vue 2 中，`v-for` 会先处理循环逻辑，生成所有的元素，然后再根据 `v-if` 的条件对其中不符合条件的元素进行销毁。这会导致性能浪费，因为元素先被创建，又马上被销毁。
2. 在 Vue 3 中，`v-if` 的优先级高于 `v-for`。
   + 在 Vue 3 中，`v-if` 的优先级高于 `v-for`，这意味着 `v-if` 会先判断条件，但此时 `v-for` 中的迭代数据（如 `item` 和 `index`）还没有被处理，导致无法使用循环中的数据。这会使条件判断失效。

为了避免上述问题，我们可以使用 Vue 的空文档标记标签 `template` 来分离 `v-for` 和 `v-if` 的逻辑。

+ `template` 是一个占位符标签，它本身不会渲染到页面中，而是作为一个逻辑容器。
+ `template`不能和`v-show`一起使用
+ 在 Vue 3 中，`template` 和 `key` 可以一起使用， Vue2中不行



## v-on

`v-on` 指令, 简写为`@`。`v-on` 是用来实现事件绑定的

```vue
<button v-on:click="方法名">按钮</button>  
<button @click="方法名">按钮</button>  
```



在`new Vue`时: 

1. 在 Vue 实例创建阶段，`methods` 中的每一项会被挂载到 Vue 实例上。
2. Vue 使用 `bind` 方法处理这些方法，使它们的 `this` 永远指向 Vue 实例。
   + 不要直接使用箭头函数，因为箭头函数的 `this` 是`静态绑定`的，不会指向 Vue 实例。
3. 最终挂载到 Vue 实例上的方法是经过 `bind` 处理后的版本，而不是我们直接定义的方法。

总结一下，当我们在 Vue 实例的 `methods` 中定义方法时，这些方法会在 Vue 实例创建阶段挂载到实例上。

挂载后的方法是经过 `bind` 处理的，确保方法中的 `this` 永远指向 Vue 实例。  并且在调用时会默认传入原生的事件对象



在vue中，指令最终会被解析为指令对象进行处理。指令对象包含以下内容：

| **字段**       | **说明**                                          |
| -------------- | ------------------------------------------------- |
| **name**       | 指令的名称（如 `click`）。                        |
| **modifiers**  | 一个对象，包含修饰符信息（如 `{ stop: true }`）。 |
| **value**      | 指令的表达式（如 `fn2(10, 20)`）。                |
| **arg**        | 指令的参数（如事件名称 `click`）。                |
| **expression** | 字符串形式的表达式（如 `"fn2(10, 20)"`）。        |
| **rawName**    | 指令的原始名称（如 `@click`）。                   |

`expression`

- **`expression`** 保存的是指令绑定的**原始表达式**，以字符串形式存在。

- 无论是事件绑定（如 `@click="fn2(10, 20)"`）还是动态绑定（如 `v-bind:title="dynamicTitle"`），`expression` 的值都是传入的表达式的**字符串形式**。

- ```js
  {
    name: "on",
    value: "fn2(10, 20)", // 字符串形式
    expression: "fn2(10, 20)", // 字符串形式
    arg: "click",
    rawName: "@click"
  }
  ```

  

`value`

- **`value`** 是表达式的**运行时计算结果**。

- 对于动态绑定（如 `v-bind:title="dynamicTitle"`），`value` 是 `dynamicTitle` 的实际值（比如 `"动态标题"`）。

- 对于事件绑定（如 `@click="fn2(10, 20)"`），`value` 和 `expression` 是相同的，因为事件绑定通常直接使用表达式的字符串形式，而不会进行计算。

- ```js
  {
    name: "bind",
    value: "2", // 计算后的结果
    expression: "1 + 1", // 原始字符串
    arg: "title",
    rawName: "v-bind:title"
  }
  ```



**编译原理**

```html
<button v-on:click="方法名">按钮</button> 
```

最终会被转换为

```js
button元素.addEventListener('click', e => {
  // 对事件修饰符进行响应处理
  // ...
  
  // 1. 方法在初始化时已经被挂载到组件实例，并且内部this指向组件实例
  方法(e)
}, {
  // ...
})
```



**参数传递**

这样写并不会立即执行 `fn2` 方法，而是等到点击时才会执行。也就是说，`fn2(10, 20)` 只是一个字符串形式的属性值，Vue 会在事件触发时解析并执行它。

```html
<button @click="fn2(10, 20)">按钮</button>
```



这里的 `$event` 是 Vue 提供的特殊变量，表示当前的事件对象。通过这种方式，我们既可以传递自定义参数（`10` 和 `20`），也可以传递事件对象。

```html
<button @click="fn2(10, 20, $event)">按钮</button>
```



如果只传递方法名（比如 `@click="fn2"`），Vue 会默认传递事件对象作为参数。

```html
<button @click="fn2">按钮</button>
```



**修饰符**

Vue 提供了许多修饰符，`.stop` 只是其中之一。修饰符的语法是直接在事件名后加 `.`，比如：

```html
@事件名.修饰符="方法"
```

修饰符可以连用，比如：

```html
@事件名.修饰符1.修饰符2="方法"
```



| **事件修饰符** | **作用**                                                   |
| -------------- | ---------------------------------------------------------- |
| `.stop`        | 阻止事件冒泡。                                             |
| `.prevent`     | 阻止默认事件行为。                                         |
| `.self`        | 仅当事件是从自身触发时才触发回调（忽略子元素触发的事件）。 |
| `.once`        | 事件只触发一次。                                           |
| `.capture`     | 使用事件捕获模式（事件从外向内传播）。                     |
| `.passive`     | 提升滚动性能，表示事件监听器不会调用 `preventDefault()`。  |



`.passive` 修饰符的作用是：告诉浏览器，事件处理函数不会调用 `event.preventDefault()`。这样可以提升滚动性能，尤其是在移动端。

也就是说不用在事件函数处理完在执行默认行为，而是同时执行，这样可以更流畅

如果你使用了 `.passive` 修饰符，就不能在事件处理函数中调用 `event.preventDefault()`，否则会导致控制台抛出警告。



Vue 的修饰符实际上是基于原生 JavaScript 的事件处理机制封装的。例如：

- `.stop` 会调用 `event.stopPropagation()`。
- `.prevent` 会调用 `event.preventDefault()`。
- `.capture` 会设置 `addEventListener` 的第三个参数为 `{ capture: true }`。
- `.self` 会在事件处理函数中添加一个 `event.target === event.currentTarget` 的判断。
- `.once` 会设置 `addEventListener` 的第三个参数为 `{ once: true }`。
- `.passive` 会设置 `addEventListener` 的第三个参数为 `{ passive: true }`。



Vue 支持一些常见的按键修饰符，例如：

- `@keyup.enter`：Enter 键。
- `@keyup.tab`：Tab 键。
- `@keyup.delete`：Delete 键。
- `@keyup.esc`：Esc 键。
- `@keyup.space`：空格键。
- `@keyup.up`：方向键上。
- `@keyup.down`：方向键下。
- `@keyup.left`：方向键左。
- `@keyup.right`：方向键右。



**自定义按键修饰符**：

- 你还可以通过 `Vue.config.keyCodes` 自定义按键修饰符，例如：

  ```javascript
  Vue.config.keyCodes = {
    kk: 13 // 自定义按键修饰符 "kk" 对应回车键
  };
  ```

  然后在模板中使用：

  ```html
  <input @keyup.kk="submitForm">
  ```

  `Vue.config` 是  vue的全局配置



**组合按键**：

- Vue 支持组合按键，例如：

  ```html
  <button @click.ctrl="save">保存</button>
  ```

  这个例子表示只有在按住 `Ctrl` 键的同时点击按钮时，才会触发 `save` 方法。



**`.exact` 修饰符**：

- 用于精准匹配按键组合。例如：

  ```html
  <button @click.ctrl.exact="save">保存</button>
  ```

  这个例子表示只有按住 `Ctrl` 键且没有按其他系统修饰键（如 `Alt` 或 `Shift`）时，才会触发 `save` 方法。

  注意`ctrl + 非系统修饰键`是可以触发save方法的



**Vue 和 React 的事件绑定区别**

Vue 的 `v-on` 是直接在元素上绑定事件，而 React 使用的是合成事件（Synthetic Event）。

React 的合成事件是通过事件委托实现的，事件会统一绑定到根容器上（React 16 是 `document`，React 18 是 `root`），然后通过冒泡或捕获机制分发到具体的组件上。

Vue 的事件绑定方式更加贴近原生 DOM，而 React 的合成事件则提供了更强的跨平台兼容性。

所以列表循环中，vue需要自己进行事件委托，而React不需要

## v-model

`v-model` 的主要作用是绑定表单元素（如 `input`、`textarea` 等）与组件的状态，使得表单内容的变化能够实时更新到状态，同时状态的变化也会更新到表单内容。「 双向数据绑定 」

`v-model`本质是语法糖写法

+ `<input :value="msg" @input="event => msg = event.target.value">`
  + 也可以写成 `<input :value="msg" @input="msg = $event.target.value">`
  + 即直接写事件逻辑，会被vue包裹为方法，并将`$event`替换为原生事件对象
+ 被简写为
+ `<input v-model="msg">`



**修饰符**

1. lazy
   + 默认情况下，`v-model` 监听的是 `input` 事件，即用户输入过程中就会实时更新状态值。
   + 如果加上 `lazy` 修饰符，监听事件会变为 `change`，只有用户完成输入并离开输入框时才会更新状态值。

2. number
   + 默认情况下，表单输入的内容是字符串。如果加上 `number` 修饰符，Vue 会自动将输入的内容转为数字。
   + 如果 input 元素的 type属性为 number ，number修饰符会被自动生效，即使没有被添加

3. trim
   + 默认情况下，表单输入的内容可能包含首尾空格。如果加上 `trim` 修饰符，Vue 会自动去除输入内容的首尾空格。

   + 推荐这个修饰符一直加上，除非有number修饰符了



**表单元素与事件对照表**

| 表单元素            | 绑定属性  | 监听事件 |
| ------------------- | --------- | -------- |
| 文本框 (`text`)     | `value`   | `input`  |
| 文本域 (`textarea`) | `value`   | `input`  |
| 单选框 (`radio`)    | `checked` | `change` |
| 复选框 (`checkbox`) | `checked` | `change` |
| 下拉框 (`select`)   | `value`   | `change` |

1. 绑定的值

   + 单选表单元素（如单选框或下拉框）通常绑定具体值（字符串或数字），因为它们只能选择一个选项。
   + 多选表单元素（如多选复选框）绑定数组，因为它们可以选择多个选项。

   

2. 默认情况下，单个复选框的`v-model`绑定的是布尔值：

   - 勾选时绑定 `true`。
   - 未勾选时绑定 `false`。

   可以通过`true-value`  和`false-value`属性自定义绑定值。例如：

   ```vue
   <input type="checkbox" v-model="checked" true-value="yes" false-value="no">
   ```

   在这种情况下：

   - 勾选时绑定值为 `"yes"`。
   - 未勾选时绑定值为 `"no"`。

   

3. 下拉框的 `v-model` 绑定的是选中 `option` 元素的 `value` 属性值。

   ```vue
   <select v-model="selectedOption">
     <option value="option1">Option 1</option>
     <option value="option2">Option 2</option>
   </select>
   ```

   - 如果用户选择了 "Option 1"，`selectedOption` 的值会变成 `"option1"`。
   - 如果用户选择了 "Option 2"，`selectedOption` 的值会变成 `"option2"`。

import { ref } from 'vue'

const selectedOption = ref('option2') // 默认选中第二个radio
</script>

<template>
  <input v-model="selectedOption" type="radio" name="example1" value="option1"> 选项 1
  <input v-model="selectedOption" type="radio" name="example2" value="option2"> 选项 2

    2. 单选按钮 被选中后，除非选择同组中另一个单选按钮，或通过js脚本取消，否则是无法取消的
    3. v-model 绑定的状态值 如果是同一个状态值 就是同一个分组 
			 + 在 HTML 中，一组单选框通常通过 `name` 属性进行分组，确保同组内只能选中一个选项
    4. 单选框的选中状态由 `v-model` 的绑定值与单选框的 `value` 属性匹配决定
  -->
  <p>当前选中值：{{ selectedOption }}</p>
</template>
```

<!-- 单选框 值一般推荐绑定为 布尔值  -->
<input type="radio" v-model="isRequired" :value="true"> 必填

```js
// 伪代码

// 假设绑定的状态值为 sex
let sex = 0; // 初始值为 0

// 渲染阶段
document.querySelectorAll('input[type="radio"]').forEach(radio => {
  if (radio.value == sex) {
    radio.checked = true; // 匹配成功，设置为选中
  } else {
    radio.checked = false; // 匹配失败，取消选中
  }
});

// 监听用户操作
document.querySelectorAll('input[type="radio"]').forEach(radio => {
  radio.addEventListener('change', () => {
    if (radio.checked) {
      sex = radio.value; // 更新状态值为选中项的 value 值
    }
  });
});
```

**单选框与复选框的区别**

1. **选中状态的切换**  
   - 单选框：一旦选中后，不能通过点击使其取消选中。
   - 复选框：可以通过点击自由切换选中和取消选中状态。
2. **多选能力**  
   - 单选框：同一组内只能选中一个。
   - 复选框：可以选中多个选项。

```vue
<template>
  <div>
    <input type="checkbox" v-model="rememberMe"> 记住我
    <p>当前选中状态：{{ rememberMe ? '选中' : '未选中' }}</p>
  </div>
</template>

<script>
export default {
  data() {
    return {
      rememberMe: true // 默认选中
    };
  }
};
</script>
```

```js
// 伪代码

// 假设绑定的状态值为 rememberMe
let rememberMe = false; // 初始值为 false

// 渲染阶段
document.querySelectorAll('input[type="checkbox"]').forEach(checkbox => {
  checkbox.checked = !!rememberMe; // 根据状态值设置选中状态 「 非布尔值会转换为布尔值 」
});

// 监听用户操作
document.querySelectorAll('input[type="checkbox"]').forEach(checkbox => {
  checkbox.addEventListener('change', () => {
    rememberMe = checkbox.checked; // 更新状态值为选中状态
  });
});
```

**总结**

Vue 中表单操作的核心规律可以总结为以下几点：

1. **状态值的类型**：
   - **单选**：`v-model` 绑定的状态值是一个普通变量，表示选中的 `value` 值。
   - **多选**：`v-model` 绑定的状态值是一个数组，表示选中的多个选项的 `value` 值。

2. **状态值与 `value` 的关联**：
   - `v-model` 绑定的状态值与表单项的 `value` 属性进行匹配。
   - 当状态值与某个表单项的 `value` 匹配时，该表单项会被选中。
   - 当用户切换选中项时，`v-model` 会自动更新状态值。

3. **特殊情况：单个复选框**：
   - 单个复选框的状态值是布尔值（`true` 或 `false`），表示是否选中。
   - 无需设置 `value` 属性，选中状态由绑定的布尔值控制。



## v-pre

`v-pre` 指令会告诉 Vue **跳过该元素及其子元素的编译过程**

这意味着 Vue 不会解析模板语法，也不会动态绑定数据。该元素和子元素会直接以原始内容渲染到页面上。

```html
<h2 v-pre>{{ title }}</h2>
```

在实际项目中，`v-pre` 的主要用途是优化渲染性能，尤其是对于**静态内容**。 因为静态内容不需要 Vue 的模板解析或虚拟 DOM 对比。

在 Vue 3 中，Vue 3 会自动跳过静态内容的编译。无需手动添加 `v-pre`，Vue 3 会识别哪些内容是静态的，并跳过相关的编译步骤。



## v-cloak

`v-cloak` 的主要作用是：

- **防止模板语法闪烁**：
  - 在 Vue 的 JavaScript 文件未加载完成或 Vue 实例未初始化之前，页面上可能会显示模板语法（如 `{{ message }}`）。等渲染完成后，模板内容又会被替换为最终渲染结果，从而出现闪烁效果
- 通过 `v-cloak`，可以隐藏这些未渲染的模板内容，直到 Vue 完成编译和渲染。
- `v-cloak`需要和css样式一起结合使用
  - 在 Vue 完成编译之前，`v-cloak` 会作为一个属性存在于元素上。
  - 我们通过 CSS 隐藏带有 `v-cloak` 属性的元素。
  - Vue 完成编译后，会移除 `v-cloak` 属性，元素随之显示。

```vue
<div id="app" v-cloak>
  <h2>{{ title }}</h2>
</div>

<style>
  [v-cloak] {
    display: none;
  }
</style>
```

- 在非工程化项目中，`v-cloak` 很有用，可以隐藏未渲染的模板内容。
- 在工程化项目中，由于模板内容通常在 JavaScript 中生成，`v-cloak` 的使用场景较少。
  - 工程化项目中，组件模板已经在构建时候就已经完成了对应编译，变成了render函数
  - 这也就意味着
    1. 界面不可能存在闪烁效果
    2. vue只需要引入必要的运行时脚本就行，不用引入整个vue「 runtime + compiler 」



## v-once

`v-once`适用于静态内容或不需要响应式更新的内容。

```html
<h2 v-once>{{ title }}</h2>
```

使用 `v-once` 的元素会在 Vue 的虚拟 DOM 中被标记为静态节点。静态节点不会参与后续的 DOM 更新流程，从而提高渲染性能。

指定的元素及其子元素只会在首次渲染时被编译。后续即使状态发生变化，视图也不会更新。即只会被渲染一次。



## v-memo

1. 缓存一个模板的子树。在元素和组件上都可以使用
2. 为了实现缓存，该指令需要传入一个固定长度的依赖值数组进行比较
3. 如果数组里的每个值都与最后一次的渲染相同，那么整个子树的更新将被跳过

```vue
<div v-memo="[valueA, valueB]">
  ...
</div>
```

当组件重新渲染，如果 `valueA` 和 `valueB` 都保持不变，这个 `<div>` 及其子项的所有更新都将被跳过。实际上，甚至虚拟 DOM 的 vnode 创建也将被跳过，因为缓存的子树副本可以被重新使用。

`v-memo` 传入空依赖数组 (`v-memo="[]"`) 将与 `v-once` 效果相同。

`v-memo` 仅用于性能至上场景中的微小优化，应该很少需要。最常见的情况可能是有助于渲染海量 `v-for` 列表 

如果`v-for`和`v-memo`同时使用，则他们必须在同一个元素上，`v-for`中的`v-memo`会静默失效
