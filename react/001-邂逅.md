## 数据驱动

目前，相对来说比较知名的前端框架主要是 **React**、**Vue.js** 和 **Angular 「 NG 」**

而这些现代前端框架都是声明式框架，即按照框架提供的语法和规则编写应用

目的是让我们只需要关注业务逻辑和数据处理，至于界面的渲染和更新交给框架来实现

简单来说就是**将DOM操作外包给了框架来实现。我们只需要修改状态，界面会自动更新**



传统开发思路是 想操作谁就获取谁，通过事件监听的方式处理业务逻辑，并将处理后的结果通过操作DOM方式更新到界面上。

但这样存在如下问题:

1. 需要自己频繁操作DOM，需要自己手动避免页面的重排「 回流 」和重绘 => 会比较消耗性能
2. 既要处理业务逻辑，还要关心界面渲染和更新，不利于后期维护



虽然现代框架的底层本质也是在操作DOM，但其实现了从虚拟 DOM 到真实 DOM 的渲染体系。

VDOM是框架内部自己定义的一个对象，用来表示「描述」界面中的真实DOM。也就是说一个真实DOM对应一个VDOM

正是因为VDOM的存在，可以通过DOM-DIFF找到最小更新补丁包。从而实现以最小代价更新界面

```jsx
import React from 'react' // react核心库 => 实现业务逻辑，并生成vdom
import ReactDOM from "react-dom/client"; // vdom => dom
// 也可以直接写成 import { createRoot } from 'react-dom/client'

/*
	其余还有
	import { renderToString } from 'react-dom/server' // vdom => html string
	import {Text, View} from 'react-native' // vdom => 移动应用 原生控件
*/
import App from "./App"; // 根组件

// 通过DOM指定 div#root 为挂载点 「 根容器 」=> 不能使用html或body「 正常渲染，但会有警告 」
// 渲染后的内容会替换挂载点中本身存在的内容
// 挂载点本身不是应用「 Web App 」的一部分，挂载点中的内容才是
const root = ReactDOM.createRoot(document.getElementById('root')); // 创建根元素

// 通过根元素去渲染应用
root.render(<App />);
```



React18之前的入口文件 「 React18之前没有并发渲染模式 」

```jsx
import React from 'react';
import ReactDOM from 'react-dom';

ReactDOM.render(<>Hello World</>, document.getElementById('root'));
```



### 状态

状态是特殊的数据，是指哪些参与界面渲染，并在值发生改变时，界面需要发生响应更新的数据

响应式数据「 响应式状态 」，即改变状态后，框架会自动监听到。无需通过调用方法通知框架重新界面更新的状态



### MVC VS MVVM

为了实现数据驱动视图渲染，现代框架都实现了一套自己的架构体系。

其中最主要的是

1. MVC 「  Model（数据层）、View（视图层）和 Controller（控制层） 」
2. MVVM 「  Model（数据层）、View（视图层）和 ViewModel（视图模型层） 」

React 框架使用的是 MVC 的体系，而 Vue 框架采用的是 MVVM 的体系

![MVC](https://s2.loli.net/2025/03/04/182odbp3lFPSGsK.jpg) 

![MVVM](https://s2.loli.net/2025/03/04/JQKRz5YNts684lj.png)  



MVC 只实现了 数据驱动视图渲染 => 单向数据驱动

MVVM在MVC基础上进行改进，在实现数据驱动视图渲染的基础上，又实现了视图改变驱动状态更新 「 主要是表单元素的改变，对应的状态值也会发生改变 」=> 这也被叫做 **双向数据驱动**



## IDE支持

Vue组件是以`.vue`结尾的SFC。而react是以`.js`或`.jsx`结尾的SFC

区别是

1. 后缀为`.jsx` => IDE自动识别JSX，并提供高亮和语法提示
2. 后缀为`.js` => 默认只有高亮，没有语法提示 => 需要手动将文件的语法解析规则修改为`JSX`

`.jsx`文件本质依旧是JavaScript文件，可以看成是`.js`文件 + `文件语法解析规则修改`的快捷方式

`.js`和`.jsx`最终都会被交给`babel`这类工具进行解析。

## 异步渲染

异步渲染是一种思想，而React通过并发模式（ Concurrent Mode）进行实现，但这只是异步渲染的一种具体实现方式，并不是唯一实现方式

### 传统渲染的特点

- 传统的 React 渲染是同步的。

- 当 React 开始更新组件树时，它会从根组件开始递归地更新子组件，直到整个更新过程完成为止。

- 在这个过程中，React 会占用主线程，其他任务（如用户输入、动画等）无法执行，直到渲染完成。这可能导致用户界面卡顿，尤其是在渲染任务复杂或组件树很大的情况下。

传统渲染就像一个高优先级的任务独占 CPU，不释放时间片，直到它完成为止。这种方式虽然简单，但对实时交互的用户体验不友好。



### 异步渲染的特点

- React 的异步渲染会将渲染任务拆分成多个小任务（分片），并将这些任务分配优先级。
- React 会根据任务的优先级动态调度这些任务。例如：
  - 用户输入或动画等高优先级任务会被优先处理。
  - 后台数据加载或低优先级的 UI 更新会被延迟到主线程空闲时再处理。
- 在执行任务时，如果有更高优先级的任务需要处理，React 可以随时中断当前渲染任务，切换到更高优先级的任务。



异步渲染就像操作系统的时间片调度机制：

- 每个任务被分配一个时间片，任务运行一段时间后会被挂起，切换到其他任务。
- 操作系统根据任务的优先级决定哪个任务先运行。
- 高优先级任务可以随时打断低优先级任务。

React 的异步渲染依赖其内部的调度器（Scheduler），这个调度器的行为和操作系统的调度器非常类似

 React 将渲染任务分片，并在每个时间片中执行一部分任务。每个小块的执行时间很短（通常是几毫秒）。这样可以避免长时间占用主线程。

如果一个低优先级任务正在执行，而此时有更高优先级的任务到来，React 会中断当前任务，转而处理更高优先级的任务。被中断的任务不会被丢弃，而是会在主线程空闲时继续执行，直到完成



React 为不同类型的任务分配优先级。例如：

- 用户输入和动画是高优先级任务。
- 数据加载后的渲染是中等优先级任务。
- 非关键的后台更新是低优先级任务。



### React Fiber

React Fiber 是 React 的协调引擎（Reconciliation Engine），它实现了分片渲染和任务调度机制。Fiber 的调度器会根据任务的优先级来决定何时执行更新。例如，高优先级任务（如用户交互）会被优先处理，而低优先级任务（如后台数据加载或动画）可能会被延迟到浏览器的空闲时间执行。

Fiber 的调度机制与浏览器的事件循环机制类似，它会将渲染任务分割成多个小任务（分片），并在每一帧内检查是否有更高优先级的任务需要处理，从而实现了可中断的渲染。这种机制使得 React 能够在复杂场景下保持流畅的用户体验。



## pm2

`node` 启动 

1. 修改需要重启
2. 命令行界面不能关闭，否则服务会停止

`nodemon`启动

1. 自动监听文件改变，并实时重新加载
2. 命令行界面不能关闭，否则服务会停止

`pm2`启动

1. 自动监听文件改变，并实时重新加载
2. 以服务形式启动，关闭命令行界面服务依旧可以存在，甚至可以设置开启自启 => 服务持久化



```shell
pm2 start <node入口脚本> --name <服务名> # 启动服务
pm2 start <node入口脚本 | 服务名> --watch # 启动服务并实时监听
pm2 restart <node入口脚本 | 服务名> # 重启服务
pm2 stop <node入口脚本 | 服务名> # 暂停服务
pm2 delete <服务名> # 删除服务
```



## 代理

在vite内置代理配置，不需要再单独安装 http-proxy-middleware。只需要在vite.config.js中进行如下配置即可

```js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

// https://vite.dev/config/
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:9000', // 目标服务器地址
        changeOrigin: true, // 是否修改请求的源
        rewrite: (path) => path.replace(/^\/api/, ''), // 重写路径，将 '/api' 去掉
      },
    },
  }
})
```
