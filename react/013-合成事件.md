React 的合成事件「Synthetic Event」是在原生事件基础上进行的二次封装，屏蔽了不同浏览器事件底层的差异，同时进行了功能扩展

```jsx
<button
 onClick={() => console.log('冒泡阶段触发的点击事件')}
 onClickCapture={() => console.log('捕获阶段触发的点击事件')}
>click me</button>
```

## 实现原理

在 React 中，所有的合成事件都是基于事件委托机制处理的

+ 在 React 17 及以后的版本中
  + 所有事件的处理都被委托给 ID 为 `root` 的容器
  + 无论是捕获阶段，还是冒泡阶段，事件都被统一委托到 `root` 容器上
+ 在 React 17 之前的版本中
  + 事件处理是委托给 `document` 容器的
  + 只对事件的冒泡阶段进行了委托处理，而捕获阶段的事件并没有被委托

如果某些事件不支持事件传播机制，那么这些事件就无法通过委托来处理，而只能单独绑定到对应的 DOM 节点上

> 所以react无需开发者自己通过事件委托绑定事件，因为React源码已经实现
>
> 但是在Vue中，Vue并没有在内部实现这部分逻辑，开发者需要自己判断何时需要使用事件委托



在解析JSX的时候，会将`onClick`和`onClickCapture`作为VDOM的属性进行挂载，例如如下内容

```js
// 属性名是 小驼峰写法
outer.onClick = () => { console.log('outer 冒泡 合成'); };
outer.onClickCapture = () => { console.log('outer 捕获 合成'); };
inner.onClick = () => { console.log('inner 冒泡 合成'); };
inner.onClickCapture = () => { console.log('inner 捕获 合成'); };
```



在挂载容器进行事件绑定

```js
root.addEventListener('click', (ev) => {
  [...ev.composedPath()].reverse().forEach(ele => {
      let handle = ele.onClickCapture;
      // 内部是这么调用的，所以默认this为undefined
      if (handle) handle();
  });
}, true);

root.addEventListener('click', () => {
  ev.composedPath().forEach(ele => {
      let handle = ele.onClickCapture;
      if (handle) handle();
  });
}, false);
```



**示例**

```jsx
import React, { useEffect, useRef } from 'react';
import './App.css';

function App() {
  const outerRef = useRef(null);
  const innerRef = useRef(null);
  const handleClick = (name, phase, type) => console.log(`${name} ${phase} ${type}`)

  useEffect(() => {
    document.addEventListener('click', () => handleClick('document', '冒泡', '原生'));
    document.addEventListener('click', () => handleClick('document', '捕获', '原生'), true);

    document.body.addEventListener('click', () => handleClick('body', '冒泡', '原生'));
    document.body.addEventListener('click', () => handleClick('body', '捕获', '原生'), true);

    // 绑定root事件 「 root是挂载容器 」
    // 原生DOM获取方式是页面全局范围内查找对应DOM => 没有组件作用域，需要自己手动设置
    // 例如 组件根元素添加唯一样式名`app` => document.querySelector('.app .root'); 
    const root = document.querySelector('.root'); 
    root.addEventListener('click', () => handleClick('root', '冒泡', '原生'));
    root.addEventListener('click', () => handleClick('root', '捕获', '原生'), true);

    // 绑定outer和inner的原生DOM事件
    outerRef.current.addEventListener('click', () => handleClick('outer', '冒泡', '原生'));
    outerRef.current.addEventListener('click', () => handleClick('outer', '捕获', '原生'), true);
    innerRef.current.addEventListener('click', () => handleClick('inner', '冒泡', '原生'));
  }, []);

  return (
    <div
      ref={outerRef}
      className="outer"
      onClick={() => handleClick('outer', '冒泡', '合成')}
      onClickCapture={() => handleClick('outer', '捕获', '合成')}
    >
      <div
        ref={innerRef}
        className="inner"
        onClick={() => handleClick('inner', '冒泡', '合成')}
        onClickCapture={() => handleClick('inner', '捕获', '合成')}
      >
      </div>
    </div>
  );
}

export default App;
```

+ 在React17及以后触发结果

## 合成事件

1. 合成事件有`stopPropagation`, 但是没有`stopImmediatePropagation`
2. 合成事件中`stopPropagation`，即可以阻止原生事件传播也可以阻止合成事件传播
3. 合成事件`nativeEvent`对应的原生事件对象，也有`stopPropagation`，只能阻止原生事件传播，无法阻止合成事件传播

```jsx
import React, { useEffect, useRef } from 'react';
import './App.css';

function App() {
  const outerRef = useRef(null);
  const innerRef = useRef(null);
  const handleClick = (name, phase, type) => console.log(`${name} ${phase} ${type}`)

  useEffect(() => {
    document.addEventListener('click', () => handleClick('document', '冒泡', '原生'));
    document.body.addEventListener('click', () => handleClick('body', '冒泡', '原生'));

    const root = document.querySelector('.root');
    root.addEventListener('click', () => handleClick('root', '冒泡', '原生'));

    outerRef.current.addEventListener('click', () => handleClick('outer', '冒泡', '原生'));
    innerRef.current.addEventListener('click', () => handleClick('inner', '冒泡', '原生'));
  }, []);

  return (
    <div
      ref={outerRef}
      className="outer"
      onClick={() => handleClick('outer', '冒泡', '合成')}
    >
      <div
        ref={innerRef}
        className="inner"
        onClick={e => {
          handleClick('inner', '冒泡', '合成')
          // 通过合成事件对象阻止事件冒泡
          // 输出结果: inner 冒泡 原生 => outer 冒泡 原生 => inner 冒泡 合成 => root 冒泡 原生
          // 	1. 同级合成事件被阻止了 「 没有输出 outer 冒泡 合成 」
          // 	2. 同级原生事件没有阻止 「 输出了 root 冒泡 原生 」 
          //  3. 后续原生事件都被阻止了
          e.stopPropagation()
        }}
      >
      </div>
    </div>
  );
}

export default App;
```

## 事件对象池

react事件是合成事件，对应事件对象是合成事件对象，为了避免每次触发事件都需要重新生成对应合成事件对象

React16中存在事件对象池，创建完的合成事件对象在被使用后会清除相关属性被存入对象池，下次又触发相同事件时直接从池中取出对应事件对象赋值后使用即可。使用完毕再重置后重新存入对象池



但这存在一个问题，如果在异步处理中我需要使用当前事件的合成事件对象，可能根本无法获取对应属性值，因为对应合成事件对象可能已经被重置了并重新放回了合成事件池中

可以通过`e.persist()`方法，显示通知react，该事件不用存入合成事件对象池，需要一直保存直到事件处理完后销毁即可。而合成事件对象池在React17开始已经被移除



## 移动点击的300ms延迟

在移动设备浏览器中，`click` 事件存在 **300ms 的延迟**，其目的是为了区分用户的 **单击（tap）** 和 **双击缩放（double-tap zoom）** 操作。

- **单击（tap）**：用户点击屏幕一次，触发 `click` 事件。
- **双击缩放（double-tap zoom）**：用户快速点击屏幕两次，页面会放大或缩小。

为了区分这两种操作，浏览器需要等待 300ms，以判断用户是否会进行第二次点击（即双击）。如果没有第二次点击发生，浏览器才会触发 `click` 事件。

解决方法

1. 通过meta标签，禁用浏览器缩放功能 => 浏览器会自动跳过300ms延迟检测

   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">
   ```

2. 使用[FastClick](https://www.npmjs.com/package/fastclick)等第三方库，通过touch事件来模拟点击事件，从而避免300ms的延迟问题

3. 通过`touch-action` 这个css属性

   ```css
   html {
     /* 显示通过css样式告诉浏览器，不需要处理双击缩放网页行为 */
     touch-action: manipulation;
   }
   ```
