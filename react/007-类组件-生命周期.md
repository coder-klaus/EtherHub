创建类组件的语法就是创建一个类，但是这个类必须满足如下条件

1. 继承 React 提供的 `Component` 或者 `PureComponent`
   + 组件实例上会挂载几个重要的属性，包括 `props`、`context`、`refs`，以及一个内部的 `updater`
2. 必须需要实现一个 `render()` 方法，在这个方法中返回组件的 JSX 视图 或者 React 的虚拟 DOM

   + 在 `class` 的语法中，`render` 方法实际上是自动挂载到类的原型上的



render 函数在渲染的时候，如果 type 是：

- 字符串：创建一个标签

- 普通函数：把函数执行，并且把 props 传递给函数 => `组件(props)`

- 构造函数：把构造函数基于 new 执行「也就是创建类的一个实例」，也会把解析出来的 props 传递过去

  =>  `new 组件(props)`



组件可以实现同一个组件被多次调用，并且互相之间不会有直接的影响

+ 函数组件每次调用都会产生一个新的执行上下文，从而保证了互相之间的独立性
+ 类组件每次调用是通过创建一个新的实例，来保证实例之间的独立性

所以，无论是函数组件还是类组件，同一个组件都可以被多次调用，并且可以同时被调用多次，互相之间不会有影响。



在类组件中，框架会自动调用你定义的 **render** 方法，返回的内容就是组件的渲染结果「VDOM」。这个结果会被转换为实际的 DOM 元素并渲染到页面上。

```jsx
import { PureComponent } from 'react'

export default class App extends PureComponent {
  // 组件的构造函数, 调用组件react会自动执行该构造函数
  constructor(props) {
    // 子类构造函数必须先调super才能正常初始化子类实例
    super(props) // 调用父类构造函数初始化props => 将props挂载到组件vdom的props属性上
  }

  // 唯一一个必须执行的方法，内部this为组件实例，必须返回JSX视图
  render() {
    const { name, age } = this.props

    return (
      <>
       { name } --- { age }
      </>
    )
  }
}
```



如果你没有写 `constructor` 或没有在 `constructor` 中调用 `super(props)`，React 仍然会自动挂载 `props`。

在组件的其他方法中，只需通过 `this.props` 就能获取到传递进来的属性。

```jsx
import { PureComponent } from 'react'

export default class App extends PureComponent {
  // 即使在构造函数中this为undefined，在其余方法中依旧可以正常获取props
  constructor() {
    super()
    // 在类组件中，通过 this.props 获取的属性，默认也是被冻结的
    console.log(this.props)
  }

  render() {
    const { name, age } = this.props

    return (
      <>
       { name } --- { age }
      </>
    )
  }
}
```



甚至于，如果你完全没有写 `constructor`，React 也会自动处理这些逻辑。

也就是说，无论你是否在 `constructor` 中显式处理，React 都会确保 `this.props` 在 `render` 方法中可用，并且包含传递进来的属性值

```jsx
import { PureComponent } from 'react'

export default class App extends PureComponent {
  // 直接通过类表达式定义状态 => 省略构造函数
  state = {
    name: 'Klaus'
  }

  render() {
    return (
      <>
       { this.state.name } --- { this.props.age }
      </>
    )
  }
}
```

状态有一个很重要的特点：**后期修改状态时，可以触发视图的重新渲染**。

在类组件中，初始化状态就是给实例对象添加一个 `state` 属性。我们通常会在构造函数 `constructor` 中，通过 `this.state` 来定义状态。

  };

**直接修改状态值只能改变数据本身，但无法让视图更新**，React 对直接修改状态的行为是“无感知”的。 React 的状态更新机制要求你通过 `setState` 或 `useState` 的 **setter 函数** 来更新状态

在 React 的组件原型（`React.Component`）上，有两个重要的方法：

1. **`setState`**
   + 这个方法的作用是**修改状态，同时触发视图更新**。也就是说，`setState` 是 React 中用来更新状态的标准方式。
2. **`forceUpdate`**
   + 无论你有没有操作状态，哪怕你什么都没改动，只要执行了 **`forceUpdate`**，组件都会被强制更新一次 「 不推荐使用 」
   + `forceUpdate` 强制更新的特点就是无视 `shouldComponentUpdate` 的返回值，直接更新视图
   + 此时组件会跳过SCU，并执行后续生命周期钩子 「 如 `componentWillUpdate`、`render` 和 `componentDidUpdate` 」
   + 使用`forceUpdate`后，即使props和state都没有改变，依旧会将整个DOM-DIFF流程走完，但因为没有patch，所以没有任何真实DOM的更新

```jsx
import React, { PureComponent } from 'react'

export class App extends PureComponent {
  state = {
    count: 0
  }

  render() {
    const { count } = this.state

    return (
      <>
        <div>{ count }</div>
        <button onClick={
          () => {
            // 传入的对象会和state对象自动合并
            this.setState({
              count: count + 1
            })

            // 状态更新是异步的，会被纳入更新队列，并在合适的时机批量化更新
            console.log(this.state.count) // 0 => 所以此时状态还没有更新
          }
        }>+1</button>
        <button onClick={
          () => {
            this.state.count--

            // 强制刷新，不推荐
            this.forceUpdate(() => {
              /* forceUpdate可以传入一个可选的回调函数，该回调会在componentDidUpdate之后执行 */
              console.log('forceUpdate中的回调，会在componentDidUpdate之后执行')
            })
          }
        }>-1</button>
      </>
    )
  }

  componentDidUpdate() {
    console.log('componentDidUpdate')
  }
}

export default App
```



## 状态的不可变性

状态的不可变性指的是：**状态对象一旦创建，就不能直接修改其内容**。如果需要更新状态，必须创建一个新的状态对象，并通过 React 提供的 `setState` 或 `useState` 来替换旧的状态

状态的不可变性主要是为了保证 React 的高效性和可预测性。以下是几个核心原因：

**(1) 简化组件的重新渲染逻辑**

React 通过比较新旧状态来决定是否重新渲染组件。如果状态是不可变的，那么比较两个状态对象时，只需要检查它们的引用是否发生变化，而不需要逐个检查对象的每个属性。这大大提高了性能。

**(2) 保持数据的可追溯性**

不可变的数据可以让状态的变化更加可控。每次状态更新都会生成一个新的状态对象，这样可以轻松地回溯到之前的状态（比如在调试时使用 React DevTools 或实现时间旅行功能）。

**(3) 避免副作用**

直接修改状态对象可能会导致意外的副作用，因为多个地方可能引用同一个状态对象。如果直接修改状态，可能导致难以预测的错误。而不可变性可以避免这种问题。



## 生命周期

**周期函数**或者**钩子函数**，指的就是在组件的某些特定时间节点（比如初始化、更新、销毁）会被**自动调用**的函数。React 提供了这些函数，让我们可以在组件的不同阶段执行特定的逻辑，比如初始化数据、更新状态、清理资源等等。

钩子函数类似于一种“回调机制”，它允许我们在程序运行的特定阶段插入自定义逻辑



React 的新版本（从 16.3 开始）已经将一些生命周期函数标记为“不安全”，比如 `componentWillMount`、`componentWillReceiveProps` 和 `componentWillUpdate`。这些函数被认为在一些场景下可能会引发问题，尤其是 React 的异步渲染（如 Concurrent Mode）中。

官方推荐使用更现代、更安全的替代方案，比如 `componentDidMount` 或者在函数组件中使用 `useEffect` 钩子。

+ 在普通模式下
  + 如果使用了过时的生命周期钩子，会在控制台抛出黄色警告
  + 如果一定要用必须加上``UNSAFE_`前缀，例如`UNSAFE_componentWillMount`。控制台才会取消警告
+ 在React严格模式下
  + 如果使用了过时的生命周期钩子，会在控制台抛出黄色警告
  + 如果加上`UNSAFE_`前缀，例如`UNSAFE_componentWillMount`。控制台会抛出红色警告



React 的 Strict Mode（严格模式），它跟 JavaScript 的严格模式不是一个东西。他会去检查 React 中的一些不规范的用法或者一些不建议使用的写法 。如果你用了这些不建议使用的东西，那么它就会在控制台上抛出红色警告或者错误提示

我们写代码的时候，我一般会把这个模式（Strict Mode）去掉。 因为有一些 UI 组件库开发得比较早。如果我们在这边开启了 React 的 Strict Mode（严格模式），然后用到了一些相对来说比较老版本的 UI 组件库或者插件的时候，它就会在控制台里抛出很多警告

     componentDidMount() {

   }

1. 更新阶段

   假设调用方式如下

   ```jsx
   root.render(<App name="Alex" />)
   
   setTimeout(() => {
     console.log('rerender')
     root.render(<App name="John" />)
   }, 2000)
   ```

   则

   ```jsx
   import React, { Component } from 'react'
   
   export class App extends Component {
     state = { count: 0 }
   
     // 组件即将接收并初始化props => 无论props是否发生了实际变化，这个生命周期钩子都会被调用
     // 这个生命周期钩子执行时机在shouldComponentUpdate之前
     // 这是一个不安全的生命周期钩子
     UNSAFE_componentWillReceiveProps(nextProps) {
       console.log('componentWillReceiveProps')
       console.log('componentWillReceiveProps nextProps props:', nextProps, this.props) // { name: 'John' } { name: 'Alex' }
     }
   
     /*
       简称 SCU  返回布尔值 用于控制组件是否需要更新 「 需要显示返回布尔值，否则控制台会抛出警告 => 默认返回undefined是不行的 」
       所以此时组件还没有更新，参数是新的props和新的state
       如果不显示定义SCU, 则默认返回true
   
       React 通过 shouldComponentUpdate 的返回值来决定是否继续进行后续的渲染流程：
        + 如果返回 true，React 会继续更新组件，触发后续的生命周期函数（例如 render 和 componentDidUpdate 等）。
        + 如果返回 false，React 会跳过更新流程，不会重新渲染组件，也不会触发后续的更新生命周期函数。
   
       PureComponent 默认实现了自己的SCU，如果子类重写SCU会报错
       所以如果需要自定义SCU，需要继承自Component而不是PureComponent
     */
     shouldComponentUpdate(nextProps, nextState) {
       console.log('shouldComponentUpdate')
       console.log('shouldComponentUpdate nextProps props:', nextProps, this.props) // { name: 'John' } { name: 'Alex' }
       console.log('shouldComponentUpdate nextState state:', nextState, this.state) // { count: 1 } { count: 0 }
       return true
     }
   
     // 在 React 16.3 之后，已废弃
     // 组件正准备更新 「 正准备重新渲染 」
     UNSAFE_componentWillUpdate(nextProps, nextState) {
       console.log('componentWillUpdate')
     }
   
     // 更新props和state => 使用最新的props和state去进行界面渲染
     // 组件重新渲染 => 所以在render中通过this获取的state和props是最新值
     // render方法的功能就是按照最新的状态和属性生成新的虚拟DOM 「 VDOM树是全量生成的 」
     render() {
       // setState触发的状态更新是异步批处理的，所以此时this.state并没有被更新
       // 而是加入更新队列后，执行shouldComponentUpdate,UNSAFE_componentWillUpdate等方法后
       // 在界面重新渲染之前才更新state和props的值
       return <button onClick={() => this.setState({ count: this.state.count + 1 })}>{this.state.count}</button>
     }
   
     // 进行新旧虚拟DOM的对比，生成差异对象 「 patch包 」
     // 生成差异对象后，React 会使用这些差异对象来更新 DOM，而不是重新渲染整个组件。「 更新Patch包的过程是VDOM和DOM保持一致的过程，这个过程又被诚之为协同 」
   
     // 组件更新完成 => 此时界面已经更新完成，所以参数是更新前的props和state
     componentDidUpdate(prevProps, prevState) {
       console.log('componentDidUpdate')
       console.log('componentDidUpdate prevProps props:', prevProps, this.props) // { name: 'Alex' } { name: 'John' }
       console.log('componentDidUpdate prevState state:', prevState, this.state) // { count: 0 } { count: 1 }
     }
   }
   
   export default App
   ```



在 React 的组件渲染过程中，父组件的渲染会遵循一个深度优先的原则。换句话说，当父组件在渲染时，遇到子组件时，React 会优先完成子组件的渲染流程，然后再回到父组件继续完成它的渲染

所以在组件销毁的过程中，也是先销毁子组件，再回过头来销毁父组件



在整个生命周期流程中

- `componentWillMount`（已被废弃）。
- `componentWillReceiveProps`（已被废弃）。
- `componentWillUpdate`（已被废弃）。

> 基本上，除了`componentWillUnmount`之外，所有带`will`的生命周期钩子都已经被废弃

这些生命周期函数在 React 的新版本中被认为是不安全的，主要是因为它们容易导致一些意外行为，或者在新的 React 特性（如 Concurrent Mode）中表现不稳定

- 用 `getDerivedStateFromProps` 替代 `componentWillReceiveProps`。
- 用 `componentDidMount` 或其他更安全的逻辑替代 `componentWillMount`。
- 用 `getSnapshotBeforeUpdate` 替代 `componentWillUpdate`。



Hook组件 = 函数组件 + hook函数 => 静态组件动态化 => 即有函数组件的渲染速度优势，又同时可以自更新和props更新



```jsx
import React, { PureComponent } from 'react'

export class App extends PureComponent {
  state = {
    age: 18
  }

  // 1. 类方法 => 内部不能使用this => 取代 componentWillReceiveProps
  // 2. 参数1 => 传入的props 参数2 => 组件的state
  // 3. 返回值
  //    + 返回对象，会和组件state进行合并 => Object.assign(组件state, 返回的对象)
  //    + 返回null，无视发生
  //    + 返回其他值，该方法静默失效且控制台抛出警告
  static getDerivedStateFromProps(props, state) {
    return {
      doubleNum: props.num % 2 ? props.num * 2 : props.num
    }
  }

  render() {
    const { num } = this.props
    const { doubleNum, age } = this.state

    return (
      <>
        <div>{ num } --- { doubleNum }</div>
        <div>{ age }</div>
        <button onClick={() => this.handleClick()}>click</button>
      </>
    )
  }

  handleClick() {
    this.setState({
      age: this.state.age + 1
    })
  }
}

export default App
```

```jsx
import React, { PureComponent } from 'react'

export class App extends PureComponent {
  state = {
    count: 0
  }

  // 在 React 将虚拟 DOM 更新到真实 DOM 之前调用
  // 此时，新的虚拟 DOM 已经生成，但真实的 DOM 还没有更新。
  // 所以props和state还是更新前的状态和props
  getSnapshotBeforeUpdate(prevProps, prevState) {
    console.log(prevProps, prevState)
    // 该方法返回的值会作为第三个参数传递给 componentDidUpdate
    // 	+ 该方法必须返回一个非undefined值
    // 用于在 DOM 更新之前获取快照信息，比如滚动位置、光标位置等
    return {
      name: 'Klaus'
    }
  }

  render() {
    return (
      <>
        <div>{ this.state.count }</div>
        <button onClick={() => this.handleClick()} >click</button>
      </>
    )
  }

  componentDidUpdate(prevProps, prevState, snapshot) {
    console.log(prevProps, prevState)
    console.log(snapshot) // { name: 'Klaus' }
  }

  handleClick() {
    this.setState({
      count: this.state.count + 1
    })
  }
}

export default App
```
