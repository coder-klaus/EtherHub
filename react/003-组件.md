现代前端开发是围绕“组件化”和“工程化”来进行的。

组件化开发的基础是将功能模块化，而工程化则是在组件化的基础上实现组件的合并、压缩、打包等操作。



组件化开发能给我们带来哪些好处呢？

- 有利于团队协作开发：开发人员可以独立负责不同的组件，避免代码冲突。
- 有利于组件复用：一个组件可以在多个项目中重复使用，提高开发效率。
- 有利于单页应用（SPA, Single Page Application）的开发：组件化是 SPA 开发的核心思想之一。



Vue 中的组件化开发的话，它的组件主要划分为全局组件和局部组件。它里边也可以划分为函数组件「 通过 functional option 」和类组件，只不过它没有特意强调函数和类这样的概念。

在 Vue 3 当中，是不具备所谓的类组件的。在 Vue 3 当中的话，它的所有组件都叫函数组件，也没有所谓的类组件的概念。



React 中的话，没有全局和局部的概念，或者说你也可以理解为 React 中的组件全部都是局部组件。不过，我可以把某个组件挂载到 React 上，这样每个组件当中只要导入 React，就可以使用这个组件了。



React 中的组件主要分为三类：函数组件、类组件，还有我们的HOOK组件。



React中的SFC是以`.js`或`.jsx`结尾的文件。

+ 视图组件  => `src/views` 或 `src/pages`



函数组件是接收props，并返回JSX视图「 JSX元素 」或 虚拟dom对象的函数

## 静态组件和动态组件

| 分类     | 特点                                                         | 示例                 |
| -------- | ------------------------------------------------------------ | -------------------- |
| 静态组件 | 1. 只能props更新 「 传入新的props，重新调用返回新的JSX视图 」<br />2. 无法自更新 「 组件自身状态更新，导致界面更新 」 | 函数组件             |
| 动态组件 | 1. 可以props更新<br />2. 也可以自更新                        | 类组件<br />HOOK组件 |



函数组件第一次渲染完成后，它的内容长什么样，页面上显示的就是什么样子，这个状态不会因为组件内部的某些操作而触发函数组件的更新

但需要注意的是，组件内部的变量值确实会发生变化，只不过这些变化不会反映到页面上。正因为如此，我们把它称为‘静态组件’。

只有父组件重新调用了这个函数组件，才能触发它的更新



这是因为 React 的渲染机制依赖于 **状态（state）** 或 **属性（props）** 的变化来触发组件的重新渲染。如果你没有使用 React 提供的状态管理工具（如 `useState`），而仅仅是修改了一个普通变量，这个变量的变化不会被 React 感知，因此不会触发重新渲染。



组件在第一次渲染完成之后，通过组件内部的某些操作，还能让组件再次更新的组件。这就是类组件
